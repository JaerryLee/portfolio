# 회사 프로젝트와 담당 역할

경력 정리 기준일: 2026-11-03. NC AI 근무기간은 2026-02-02부터 2026-11-01까지이며 계약 기간 종료로 근무를 마쳤다. 개별 프로젝트 상태는 아래의 마지막 확인 시점을 기준으로 한다. 프로젝트별 목적과 직접 구현한 범위를 정리한다. 팀 제품의 전체 기능과 개인 기여, PoC의 구현 결과와 실제 운영 성과를 구분한다.

## Dainos Wiki · LLM Wiki

### 출발점과 문제

흩어진 메일·대화·문서에서 업무 상태와 변경 이유를 찾기 어려웠습니다. 기존 Dainos MVP는 이메일 기반 업무 지식화·질의 동작을 확인한 뒤 종료했고 사용자 알파는 진행하지 않았습니다. 후속 Wiki는 PC 문서의 원문 보존, 주제별 지식 정리와 출처 확인에 집중했습니다.

### 설계 선택

원문과 변경 이력은 CAS·append-only Journal에 보존하고 SQLite는 재생성 가능한 검색 투영으로 둡니다. contentless FTS5·BM25로 후보를 찾은 뒤 특정 버전·구간 원문을 읽고 인용 문자열과 SHA-256을 확인합니다. LLM과 인증은 Codex·Claude 호스트가 맡습니다.

### 본인 기여

LLM 분류 제안 검증, inbox·손상 큐의 보존과 복구, 원문·사본 SHA-256 및 인용·날짜 검증, 제한 로그, Windows 파일 처리와 Linux·Windows 회귀를 구현·보완했습니다. 검색 엔진과 저장 코어 전체는 팀 구현 범위입니다.

### 완료 상태와 확인 범위

2026년 10월 기준 코어 개발은 완료됐습니다. 자동 회귀와 일부 실제 호스트 실행 기록을 확인했으며, 플랫폼·GUI별 수동 검증은 일부 남아 있었습니다. 검색 순위는 답의 신뢰도가 아니고 인용 일치는 의미적 정답을 보장하지 않습니다. --as-of는 문서 날짜 필터이며 과거 버전 질의가 아닙니다. 공개 출시·사용자 효과 검증 완료나 생산성 개선 수치는 주장하지 않습니다.

## Dainos Finder — 계약 검토 웹·API

React·TypeScript 웹과 FastAPI·PostgreSQL API에서 검토 단계, 근거 확인, 초안·승인 이력, 로그인과 HTTP·SSE 연동을 구현했다. PostgreSQL 행 잠금과 입력 버전 검사로 오래된 결과가 새로운 상태를 덮어쓰지 않도록 했다. 판단 Agent는 팀의 별도 담당 범위다.

2026-10-22 기준 R0 웹·API 구현과 고정 Agent 응답 기반 회귀 검증을 확인했다. 당시 실제 Agent 통합과 사용자 수동 인수 검증은 진행 중이었으며 근무 종료 후 완료 여부, 판단 정확도와 상용 운영 상태는 확인하지 않았다.

## Agent Platform — Agent PoCs와 LLM Ops

정부 과제의 목표지향 업무 에이전트 PoC를 개발·인계했다. 메일·문서를 업무와 지식으로 연결하는 흐름에서 개인 담당 범위의 기능 통합을 수행했다. 메일 검색·요약 에이전트와 Pydantic AI 실행 기반 등 관련 PoC 및 LLM 실행 관측에도 기여했다. 정부 과제 성격과 인계·후속 관계는 사용자 확인 사실이며, 인계 기관·사업명·과제 규모·성과 수치는 추가하지 않는다. 같은 프로젝트의 Core·Orchestrator·BFF·FE를 독립 PoC로 세지 않는다.

- 에이전트 실행·승인과 DBOS 세션 관리, 사용자별 접근 범위 격리를 구현했다.
- 웹 콘솔·BFF·지식 서비스와 메일 검색·요약 흐름을 연결했다.
- PostgreSQL 기반 Agent 메모리·세션·이벤트 저장과 pgvector 임베딩 검색을 활용했다.
- OpenTelemetry와 내장 LLM 계측을 통합해 요청 문맥, 로그·트레이스·메트릭의 수집 경로를 연결했다.

공유 관측 인프라와 지식 추출 알고리즘 전체의 단독 개발, PoC의 공식 운영 전환이나 성능 개선 수치를 주장하지 않는다. Logfire·Opik은 사용 경험이 있는 도구이며 SDK 자체 개발을 의미하지 않는다.

## VAETKI Commerce — 배너 기능 백엔드

상품 이미지와 대화형 요청으로 배너를 생성·편집하는 기능의 전체 백엔드와 AI 서비스 연동을 개발했다. 담당 범위는 배너 기능이며 Commerce 전체 서비스는 아니다.

- 생성·조회·리사이즈·편집 API와 Redis·Celery 비동기 작업, 결과 이벤트를 구현했다.
- MongoDB 시안별 작업 잠금과 버전 조건 갱신으로 동시성 충돌을 제어했다.
- 외부 크레딧 API의 사전 예약·확정·실패 취소를 연결했다.
- 후속 썸네일 갱신이 실패해도 저장된 시안을 보존하고 재시도 경로를 제공했다.
- DEV·RC 배포 자동화를 구현했다. Live 배포는 별도 운영 담당 범위다.

작업 잠금은 MongoDB 기반이며 Redis 분산 락으로 표현하지 않는다. 크레딧 처리도 전체 작업의 DB ACID 트랜잭션이나 분산 원자성을 보장한다는 의미가 아니다.

## 기술과 검증

Python 테스트에서 pytest, unittest·mock, pytest-asyncio, FastAPI TestClient와 HTTPX를 사용했다. PostgreSQL·pgvector는 관계형 데이터, Agent 메모리·세션 실행 상태, 임베딩 저장·검색에 활용했다. 대규모 최적화·특정 벡터 인덱스 경험은 근거 없이 추가하지 않는다.

포트폴리오 사이트는 프로젝트 목적과 역할을 소개하고, 자세한 일반화된 설계 설명은 테크 블로그로 연결한다. 사이트 빌드 검증과 회사 서비스의 실제 운영 검증은 구분한다. 내부 주소·코드·자료·자격증명·개인정보·운영 수치는 공개 원고에 포함하지 않는다.
