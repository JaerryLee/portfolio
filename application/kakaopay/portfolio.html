Dainos는 메일·문서의 업무 지식을 온톨로지 기반 Knowledge Base(KB, 지식 기반)로 구축하고, AI Agent가 이를 활용해 업무 아이템을 생성하는 플랫폼입니다. KB는 업무에 등장하는 개념과 관계를 구조화해 관련 정보를 연결합니다. 이를 바탕으로 업무·문서 탐색과 근거 기반 질의응답을 지원하며, 프로젝트는 PoC(개념 검증) 단계까지만 진행됐습니다.

처리 대상과 담당 역할

KB Service는 온톨로지 기반 지식 저장·질의를 담당하는 KB Core를 제품에서 활용하도록 API·접근 권한·지식화 작업 상태를 관리합니다. 이 서비스의 요청 접수·영속 상태·재시도·결과 조회와 FE·BFF 연동을 담당했습니다. 지식 추출·그래프 알고리즘은 KB Core의 기능을 연결했으며, 별도로 에이전트 실행 기반의 AI API 비동기 호출과 세션·SSE 이벤트 전달을 구현했습니다.

관측 데이터의 수집·저장·조회 경로를 단순화한 개념도입니다.

직접 구현한 설계

  • 서비스 간 연결: FastAPI·httpx 계측과 W3C trace context·baggage 전파를 연결했습니다.
  • 하위 스팬 문맥: 요청 범위의 속성을 ContextVar에 보관하고, 새 스팬에 요청·세션 문맥을 추가했습니다.
  • 로그와 트레이스 연계: 표준 LoggingHandler를 연결해 활성 스팬의 trace ID·span ID로 오류와 호출을 함께 확인하도록 했습니다.
  • 환경별 설정: stdout과 OTLP 경로, 초기화 설정 실패 처리, 콘텐츠 수집 옵션과 헬스체크 제외를 관리했습니다.
관측 신호 확인할 수 있는 내용
Trace 서비스·모델·도구의 호출 관계와 구간별 실행 시간
Log 오류 상세와 해당 실행의 요청·세션 문맥
Metric 내장 계측이 제공하는 토큰 사용량·비용·첫 응답 지연
구현 결과

오류 로그에서 관련 실행을 찾고, 하위 모델·도구 호출의 문맥을 따라갈 수 있는 수집·조회 경로를 구성했습니다. 현재 이 관측 체계를 구축·운영하고 있습니다.

ContextVar는 별도 프로세스나 큐 경계를 자동으로 전파하지 않습니다. 수집한 지표와 실측 개선 성과는 구분합니다.
